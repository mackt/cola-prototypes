让 Agent 安全地向用户要密钥

现在模型需要 API token、密码时，只能让用户把它贴进聊天框：值会留在对话记录里、发给模型服务商、进日志。新工具 request_secret 改成：在对话里弹一张安全卡片，用户填进卡片。值只进 Cola 的临时密钥存储；模型只拿到「怎么引用它」，命令输出里出现的值会被替换成 [REDACTED:名字]。

    三、各种情况下的行为

    情况 用户看到 模型收到
    用户提供 卡片里填写并保存，卡片变成「✓ 已安全保存」 怎么引用它，不含值
    用户拒绝 点「拒绝」 用户拒绝，别再追问，说明卡在哪
    没填卡片，直接打字 卡片变成「未作答」，消息照常发出 用户发了消息、没给值，读消息接着聊
    30 分钟没响应 卡片变成「未作答」 超时，没有拿到值
    用户点停止 卡片变成「未作答」 这一轮被中断
    要长期用（比如配置 MCP） Cola 把值写进对应的配置文件，以后不用再填 只知道变量名，用命令把变量写进配置，不碰明文
    定时任务、后台任务 不会弹卡片，没人在等着回答 不可用，下次用户来时再说明需要什么

    四、讨论结论

    1. 只在本次对话里有效，最多 24 小时

      每个新对话都要重新填一次；配置 MCP 这类任务例外，值会写进配置文件长期使用。不做跨对话的「记住」：和 T3 一样，卡片上只有填写和拒绝，交互越少越好懂。

    2. 卡片放在对话时间线里

      不用弹窗，和气泡左对齐。

    3. 用户可以不理卡片，直接打字

      卡片自动变成「未作答」，Cola 读这条消息接着聊。超时只是兜底：T3 默认 10 分钟、最长 1 小时，我们现在是 30 分钟，待定。

    4. 不担心 ask_user_question 下线的原因

      那个工具下线是因为不想要一问一答式的交互，显得没人味，跟卡片的技术实现无关。

    5. 卡片文案照搬 T3

      按钮「安全保存 / 拒绝」，底部「安全存储，绝不会展示给智能体」，打开链接的按钮下面显示完整网址。

    五、已知限制

    • 少于 4 个字符的值不脱敏，否则会把普通输出改乱。
    • 长时间运行的命令，输出末尾几十个字符会晚一点出现（为了识别被切成两段的值）。
    • 命令把值换成其他编码（比如 hex）打印出来，或者 gh auth login 这类命令把值存进自己的配置文件，拦不住。
    • 写进配置文件（比如 MCP 的 servers.json）的值是明文，和用户手动配置一样。24 小时后或 Cola 重启后不再脱敏，Agent 再读这个文件会看到它。
