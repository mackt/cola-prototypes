让 Agent 安全地向用户要密钥

现在模型需要 API token、密码时，只能让用户把它贴进聊天框：值会留在对话记录里、发给模型服务商、进日志。新工具 request_secret 改成：在对话里弹一张安全卡片，用户填进卡片。值只进 Cola 的临时密钥存储；模型只拿到「怎么引用它」，命令输出里出现的值会被替换成 [REDACTED:名字]。

二、值经过哪里

明文只在下面标红的几步出现；对话记录、模型、日志里都没有。

① 用户交出 token明文

在卡片里填，提交后输入框立刻清空。

② 交给 Cola明文

只接受弹出卡片的那个窗口提交，其他客户端交不进来。

③ 临时保存明文

只放在 Cola 后台进程的内存里，24 小时过期，退出即清空。

④ 命令使用明文

本对话里 Agent 运行的命令可以引用它；其他对话拿不到。

⑤ 回到模型已脱敏

任何工具输出里出现这个值，都会先替换成 [REDACTED:名字] 再交给模型。

定时任务、后台任务 不会弹卡片，没人在等着回答 不可用，下次用户来时再说明需要什么

四、需要大家拍板的问题

  1. 一期只保存在本次会话（最多 24 小时），够不够？

    每个新对话都要重新填一次；配置 MCP 这类任务例外，值会写进配置文件长期使用。通用的「记住」放在二期，要不要提前？

  2. 卡片放在对话时间线里，还是用弹窗？

    现在跟提问卡片一样放在时间线里，等待时输入框处于「等你回答」状态。弹窗更醒目，但会挡住上下文。

  3. 超时 30 分钟合适吗？

    卡片等待期间这一轮会占着会话；太短用户来不及去网站生成 token，太长会话会卡很久。

  4. 复用 ask_user_question 的卡片链路有没有坑？

    那个工具在 #2910 被下线，提交里没写原因。需要知道当时的原因（@Shengbin），避免重复踩坑。

  5. 卡片文案

    按钮「安全保存 / 拒绝」，底部说明「不会出现在对话中，本对话里的命令可在 24 小时内使用。」需要设计和产品过一下。

五、已知限制

  • 少于 4 个字符的值不脱敏，否则会把普通输出改乱。
  • 长时间运行的命令，输出末尾几十个字符会晚一点出现（为了识别被切成两段的值）。
  • 命令把值换成其他编码（比如 hex）打印出来，或者 gh auth login 这类命令把值存进自己的配置文件，拦不住。
  • 写进配置文件（比如 MCP 的 servers.json）的值是明文，和用户手动配置一样。24 小时后或 Cola 重启后不再脱敏，Agent 再读这个文件会看到它。

六、二期计划

  • 「记住」选项：跨会话复用，可在设置里查看和删除。
  • 云端应用的 set_secret 改成按引用取值，不再让模型传明文。
  • Coding Cola、CLI 和手机端支持。
